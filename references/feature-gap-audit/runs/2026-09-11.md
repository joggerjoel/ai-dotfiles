## Critical findings unique to this run
1. qm and ai-dotfiles are different product categories. qm is a hosted multi-user runtime
   (Postgres, Fastify, Slack Bolt, Lit); ai-dotfiles provisions local coding-agent CLIs across
   an operator's machines. Comparing feature-for-feature is only meaningful at the level of
   portable patterns, plus the option of provisioning qm as a fleet target (like firstmate).
2. Near-identical command-denial floors, independently arrived at: qm's `ORG_FLOOR_RULES`
   (`src/policy/command-policy.ts`) vs ai-dotfiles' `permissions.deny` (`profiles/*/settings.json`).
   Difference: qm's is harness-independent and quote/heredoc-aware; ours applies to Claude only.
3. Both run injection screening in shadow-then-enforce mode. qm uses an LLM classifier with
   provenance labels (`internal|workspace|external`) and an explicit "unscreened" notice; ours
   is a regex PostToolUse hook. Our hook fired twice this session on qm's own rubric text and
   on its own docstring, both false positives on data.
4. ai-dotfiles has things qm does not: fleet provisioning (ansible), Prometheus/Grafana/Loki,
   11 harnesses, 3-tier model routing with a "frontier never via gateway" policy, the
   council/fusion/isolate review pipeline, prompt-cache awareness.
5. qm's `CLAUDE.md -> AGENTS.md` symlink is the same idea as our `lib/links.sh` linking
   `~/.codex/AGENTS.md`, `~/.config/opencode/AGENTS.md`, `~/.gemini/GEMINI.md` to the assembled
   CLAUDE.md. Already built here.
